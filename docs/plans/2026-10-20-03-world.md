# Plan 03 — The world: a desktop with four rooms

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

## In plain terms

Right now the learner lives in a single "crib": shapes that light up and change colour when clicked. This plan gives it a small computer to grow up in. The world becomes a **desktop** with a **taskbar**, and each taskbar icon opens a **room**:

| Room | What's in it | What the learner can discover there |
|---|---|---|
| **Crib** | shapes that react to hover and clicks | "my actions do things" |
| **Toys** | buttons, switches, sliders, draggable blocks; their state stays changed | cause and effect, things that persist |
| **Hide-and-seek** | a long page to scroll, folding sections, tabs, a pop-up to close | things still exist when they're out of sight |
| **Places** | a small linked site of 6–20 pages with links and a back button | navigation, and remembering where things are |

The learner still sees **only pixels** and acts **only** through the cursor, clicks, scroll and keys. Everything else the world knows stays on the harness side: which room is open, what's under the cursor, how much hidden content has been revealed, which page is showing. That privileged view exists so later plans can run checkups and drive the caregiver. Text is drawn from pixels using our own tiny bitmap font, so letters are something to be learned, not handed over.

When this plan is done, the live page's flailing baby lives on a four-room desktop instead of a lone crib, and every room is generated fresh from a seed so checkups can use never-seen variants. A random flailer rarely hits a taskbar icon, so in practice it mostly stays in the crib; it's the caregiver (Plan 04) that carries it between rooms.

**Goal:** a seeded, deterministic four-room desktop world behind the same `observe()` and `act()` contract, plus a privileged state and trace API for the harness, and a rendering-speed measurement (spike 3).

**Architecture:**
- `packages/world` gains a `Room` interface, a desktop shell (taskbar, focus, routing input to the active room), one module per room, a bitmap font, and a word list.
- `createWorld` keeps its signature and observation format. By default it builds all four rooms with the crib in front.
- Privileged information is exposed only through `World` methods (`state()`, `drainTrace()`, `bringToFront()`, `rooms()`) and never through `Observation`.

**Tech Stack:** TypeScript, Vitest with `@napi-rs/canvas` for Node rendering tests, Playwright for the browser rendering benchmark.

**Spec:** `docs/specs/2026-10-19-blanktab-v1-design.md` §7.1–7.2 (with §8.2 for which privileged facts later milestones need). Decisions 0005 and 0008.

## Global Constraints

- **Walls:** `world` may import only `@blanktab/interface`. Test files may use devDependencies (`@napi-rs/canvas`).
- **`Observation` is unchanged:** periphery 80×50×3, fovea 32×32×3, cursor (normalized), buttonHeld. Nothing privileged is added to it.
- **Screen:** 320×200. The taskbar is the bottom 16 px. The room viewport is 320×184 at (0,0).
- **Determinism:** the same `seed` and the same action sequence give byte-identical observations and traces. No `Math.random`, `Date` or `performance.now` inside `packages/world/src`.
- **Text is pixels:** all text is drawn with the bitmap font in `font.ts`, never with `fillText`.
- **Content is generated from seeds,** with words from `words.ts`. No external assets, no network.
- **Lockstep:** `act()` advances `tick` by exactly 1. Animations (such as pop-up timers) are driven by ticks.
- **Scroll:** one scroll action moves 16 px. Up is `scroll: 1`, down is `scroll: 2` (per `@blanktab/interface`).
- **Dependencies:** after any `npm install`, run `npm run lint && npm run typecheck && npm test`. Stop if npm reports "removed N" or "changed N" packages.
- Commit after every task.

## Review Focus

1. **Privileged leakage:** room ids, element ids, page ids and revealed fractions must never be reachable from `Observation` or `WorldView`. Test in Task 2 that the keys of `observe()`'s result are exactly `periphery`, `fovea`, `cursor`, `buttonHeld`.
2. **State persists across room switches:** a toggle switched on in Toys, a scroll offset in Hide-and-seek, and the current page in Places are all unchanged after visiting another room and coming back. Test in Tasks 3, 4 and 5.
3. **Drag that leaves the element:** pressing on a slider knob or block, moving fast past its edge, then releasing must keep the drag going until release, then drop. A press on empty space followed by a move over a block must not grab it. Test in Task 3.
4. **Scroll at the ends:** scrolling past the top or bottom clamps without error, and `revealedFraction` never exceeds 1 or decreases. Test in Task 4.
5. **Places graph:** every page is reachable from the start page by links, and Back with no history does nothing (no throw). Test in Task 5.

export const GLYPH_W = 5, GLYPH_H = 7, GLYPH_ADVANCE = 6
export function glyph(ch: string): readonly number[] | null   // 7 rows of 5-bit masks; null for unsupported chars
export function textWidth(s: string, scale?: number): number   // scale default 1
// gfx.ts
export interface Context2DLike { /* today's interface, moved here from world.ts */ }
export interface Gfx {
  rect(x: number, y: number, w: number, h: number, color: string): void
  circle(cx: number, cy: number, r: number, color: string): void

export const WORDS: readonly string[]   // ≥ 800 distinct lowercase a–z words, 2–10 letters; Ogden's Basic English list (public domain) preferred

**Interfaces:**
- Produces:

```ts
// room.ts
export type RoomKind = "crib" | "toys" | "hideseek" | "places"
export const ROOM_VIEW = { width: 320, height: 184 } as const
export interface ElementInfo { id: string; interactive: boolean; responsive: boolean }
export interface RoomEvent { kind: "click" | "respond" | "scroll" | "reveal" | "navigate" | "widget"; elementId?: string; value?: number | string }
export interface Room {
  readonly kind: RoomKind
  draw(g: Gfx): void                                    // room-local coords, viewport ROOM_VIEW
  press(x: number, y: number): RoomEvent[]              // button down at room-local point
  move(x: number, y: number, held: boolean): RoomEvent[]
  release(x: number, y: number): RoomEvent[]
  scroll(dir: "up" | "down"): RoomEvent[]
  key(k: string): RoomEvent[]                            // v1 rooms may ignore keys
  step(tick: number): RoomEvent[]                        // per-tick time (pop-up timers)
  inspect(x: number, y: number): ElementInfo | null      // privileged: element at room-local point
  areas(): { interactive: number; responsive: number; unresponsive: number }  // fractions of ROOM_VIEW area currently visible
  scrollState(): { offset: number; max: number; revealedFraction: number } | null
  page(): string | null
}
export type RoomFactory = (seed: number, words: readonly string[]) => Room
// world.ts
export interface TraceEvent {
  tick: number; room: RoomKind
  kind: "hover" | "click" | "respond" | "scroll" | "reveal" | "navigate" | "widget" | "focus"
  elementId?: string; value?: number | string
  source?: "learner" | "caregiver"          // only on "focus"
}
export interface PrivilegedState {
  tick: number; room: RoomKind; page: string | null
  cursor: { x: number; y: number }          // screen pixels
  hovered: ElementInfo | null               // includes taskbar icons: id "taskbar:<kind>", interactive & responsive
  areas: { interactive: number; responsive: number; unresponsive: number }   // of the room viewport
  scroll: { offset: number; max: number; revealedFraction: number } | null
}
export interface World extends WorldView {
  readonly tick: number
  drainTrace(): TraceEvent[]                 // privileged
  state(): PrivilegedState                   // privileged
  rooms(): readonly RoomKind[]               // privileged; taskbar order
  bringToFront(kind: RoomKind): void         // privileged: the caregiver "carries" the learner; emits focus/source "caregiver"
}
export function createWorld(opts: {
  seed: number; canvas: CanvasLike; rooms?: readonly RoomKind[]; start?: RoomKind
  roomFactories?: Partial<Record<RoomKind, RoomFactory>>   // test-only override of a kind's factory (e.g. a stub room)
}): World
  // default rooms: every implemented kind in the order crib, toys, hideseek, places; default start: first room
  // rooms must be distinct kinds (duplicate kinds throw RangeError)
```

**Shell behaviour:**
- **Taskbar:** a 16 px strip along the bottom, holding one 12×12 icon per room starting at x=4 with 4 px gaps. Each icon has its own seeded colour. The active room's icon has a 1 px light outline.
- **Clicking an icon:** a press on an icon (a learner press) brings that room forward and emits `focus` with source `learner`. `bringToFront` emits `focus` with source `caregiver`.
- **Input routing:** presses, moves, releases and scrolls go to the active room only, in room-local coordinates, and only while the cursor is in the viewport. A release always goes to the room that received the press, so a drag can end over the taskbar.
- **Hover:** a `hover` trace is emitted when the element under the cursor changes.
- **Ticks:** `step(tick)` runs on **every** room each tick, so timers continue in background rooms.
- **Cursor:** drawn last, on top of everything.
- **Seeding:** each room is seeded with `hashSeed(seed, kind)`.

**Behaviour:**

### Task 6: Rendering speed in a real browser (spike 3), and a look at every room

**Files:**
- Create: `packages/world/bench/render.html`, `render-bench.ts`, `run.mjs`. Add `bench:render` to `packages/world/package.json` (running `node bench/run.mjs`). Create `docs/research/<date>-world-render-speed.md`.

**The benchmark** (`run.mjs`, using Vite and Playwright):
1. Serve `bench/` with Vite.
2. Open `render.html` in Chromium. Its module starts a dedicated **Worker** that creates an `OffscreenCanvas(320,200)` and `createWorld({ seed: 1, canvas })`.
3. For each room (`bringToFront`), time 600 iterations of `act(random valid action from a seeded rng) + observe()`.
4. Post `{ room, msPerStep, stepsPerSec }` back, then print one JSON line per room.

It also saves one PNG per room of the full 320×200 frame (scaled 3×) to a path given by `--shots <dir>` (default: `os.tmpdir()`).

- [ ] **Step 1: Write the benchmark and run it.** Run: `npm run bench:render -w @blanktab/world`. Expected: four JSON lines. **Target: ≥ 60 steps/s per room** (render + readback + downsample), the spec §13 spike 3 bar.
- [ ] **Step 2: If any room is under target, profile it and fix the cause** (for example, re-rendering static layers each step, or per-pixel `fillRect` text drawing that should be cached into an offscreen glyph atlas). Re-run until the target is met. Record before and after.
- [ ] **Step 3: Look at the PNGs.** Each room should be legible and visibly distinct: words readable at 3×, widgets recognisable, a visible pop-up in hide-and-seek, an underlined link in places. Fix anything broken.
- [ ] **Step 4: Write the research note.** Include machine, browser version, the JSON lines, the target verdict, and what was fixed.
- [ ] **Step 5: Commit.** `bench(world): browser rendering speed per room (spike 3)`
