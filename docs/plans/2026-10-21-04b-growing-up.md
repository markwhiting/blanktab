# Plan 04b — Growing up

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

## In plain terms
The learner now learns a little: its guesses beat "nothing changes" on a fixed test (`docs/research/2026-10-21-does-it-learn-2.md`). We still can't tell whether it can *do* anything. This plan adds the three things the spec uses to watch a learner grow up:
- **A caregiver.** Like a parent carrying a baby to another room, it moves the learner to the room where it is learning fastest. Once the learner uses the taskbar by itself, the caregiver steps back and only helps when the learner is stuck everywhere.
- **Six milestones (M1–M6).** These are things a curious baby does unprompted: predicts its world, moves with purpose, prefers things that respond, uncovers hidden content, explores places efficiently, and uses the taskbar.
- **Checkups.** On the log schedule (8, 16, … 512 CU, then every 1,024 CU), learning pauses. The learner then tries each milestone in a fresh room it has never seen. Its score is how many it passes. The page draws that score over its life.

A curve of zeros is an acceptable first result (spec §2). What matters is that checkups run, are honest, and change nothing in the learner.

**Goal:** a caregiver, milestone suite v1 and checkups on fresh variants, with results in the logs and on the page.

**Architecture:**
- **Harness.** The caregiver and checkups live in `packages/harness`. Checkups use separate world instances.
- **Learner.** It gains a *frozen run*: acting and predicting with its current weights, using its own recurrent state and RNG. It never writes to the learner's state, so there is nothing to restore. A bit-exact test proves this.
- **Logs.** Results go into v2 log files as new optional fields. They follow the `evalCU` precedent: optional in the parser, strict when present.

**Tech stack:** TypeScript, Vitest, the existing `@blanktab/*` packages, `@napi-rs/canvas` in Node tests, and Playwright for the live run.

**Spec:** `docs/specs/2026-10-19-blanktab-v1-design.md` §7.2, §7.3, §8, §9.4, §14. Also decisions 0005, 0008, 0011, 0013, 0014, 0015, and the new 0016 (Task 3).

## Global Constraints
- **Earlier plans.** Every rule of Plans 04a, 04a.1 and 04a.2 still applies: walls, tensor lifecycle, cold start, the token rule, and the log and checkpoint invariants.
- **`LEARNER_STATE_VERSION` stays 2.** The only learner-state change is the additive `stats.lastLoss`. It is optional on read and NaN when absent. So live learners resume onto 04b code, and the manifest still says 2.
- **Log `schemaVersion` stays 2.** The new fields are `checkups`, `milestoneSuiteVersion` and `caregiver`. They are optional in `parseLogFile` and strict when present. Every file already in `data/runs/` must still validate.
- **`milestoneSuiteVersion` = 1, with ids `M1`–`M6`.** Changing any threshold, budget or criterion needs a new decision and a version bump (spec §8.1).
- **Checkups never train.**
  - No weight update.
  - No change to the learner's parameters, Adam state, RNG, recurrent state `h`/`last`, replay buffer, or stats other than `evalCU`.
  - Their FLOPs go to `evalCU`, never `cu`.
  - Each milestone runs in its own world instance. The main world is untouched.
  - The caregiver neither acts nor learns during a checkup.
- **Privileged state never reaches the learner.** This covers trace events, `PrivilegedState`, room names, milestone results and caregiver state (AGENTS.md invariant 2). The learner gets observations and nothing else. The caregiver acts only through `World.bringToFront`, and that is logged as a caregiver carry, never as a learner action.
- **Knowledge hash.** `computeKnowledgeSha` already lists `caregiver-prior.json` in `PRIOR_FILES` (`tools/gate/manifest.ts:12`). So adding the file **changes knowledgeSha. That is expected.** Each running tab writes one boundary log on its next knowledge refresh (decision 0014).
- **No randomness from Math.random.** Caregiver and checkup randomness comes only from seeded RNGs: `createRng` from `@blanktab/tensor`, or `hashSeed` and `mulberry32` from `@blanktab/world`.
- **Checkup budgets:** M1 300, M2 400, M3 400, M4 400, M5 400 and M6 500 steps, 2,400 in all.
  - A frozen step is forward-only, so it should run faster than the 26 training steps/s seen live. At 26 steps/s the suite would take 92 s; at around 40 steps/s, about 60 s. The M5 random-clicker reference adds 400 world-only steps.
  - Frozen steps obey the same `maxStepsPerSec` cap as learning steps (a courtesy to the visitor's machine), so expect up to about 80 s per suite. Early life is checkup-heavy (seven levels by 512 CU); that is by design: the developmental curve is densest where change is fastest.
  - Each budget is long enough for a cursor moving at most 16 px per step to cross the 320×200 screen many times. M6 gets 500 steps because three taskbar switches need repeated trips to the 16 px strip.

## Review Focus
1. **A checkup leaves the learner exactly as it was.** `save()` before and after is equal except `stats.evalCU`. A twin that never had the checkup continues bit-identically, and `cu` is unchanged. (Tasks 1, 4)
2. **A checkup that fails doesn't kill the learner.** If a milestone throws, it counts as not passed with `error: true`. The life goes on, the log is written, and `liveBuffers` returns to its pre-checkup value. GPU-recoverable errors still go through the existing restore path. (Tasks 1, 4, 6)
3. **Reloads, restores and code-reload halts never check a level twice or silently lose one.** A halt that arrives during a checkup abandons it; the checkup reruns once after the reload. (Task 6)
4. **Old data keeps working.**
   - Pre-04b logs validate.
   - Pre-04b checkpoints resume (`lastLevel` 0, caregiver from the config).
   - Summary rows without checkups show "—".
   (Tasks 2, 6, 7)
5. **Milestones can be passed, but not by flailing.**
   - Every variant leaves room to pass: interactive area < 0.5, r0 < 1, and at least 2 pages.
   - A scripted competent policy passes.
   - A seeded uniform-random policy fails each of M2–M5 on at least 9 of seeds 1–10.
   - M6's random pass rate is measured and recorded, not asserted.
   (Task 3)

  export interface FrozenResult { predLoss: number; baselineLoss: number; transitions: number }

  // TrainableLearner gains:
  frozenRun(opts: FrozenRunOptions): FrozenRun

- **Semantics:**
  - The run starts from `model.zeroState()`, with its own RNG `createRng(opts.seed)`.
  - Each `step(o_t)` mirrors `learnAndAct` without its updates:
    - if `measureLoss` and there is a previous step, it adds, with no gradient, the size-weighted prediction loss of (o_{t-1}, a_{t-1}) → o_t and that transition's `copyLastBaseline` to running **sums** (not EMAs);
    - it computes the core and heads with no gradient, and samples with `sampleAction(logits, settings.exploreEpsilon, ownRng)`.
  - `result()` returns the means, NaN with no transitions or without `measureLoss`.
  - FLOPs go to `stats.evalCU`.
  - The run never pushes to replay and never touches `h`, `hIn`, `last`, `rng`, the optimizers or any other stat.
  - While a run is open, `step`, `sleep`, `save` and `replayLoss` reject with `Error("learner: a frozen run is open (dispose it first)")`.

- **Rules:**
  - **LP mode.** It decides when `afterSleep` or `sinceDecision ≥ caregiverPeriod`. It picks room i with probability `(1 − ε)·softmax(LP/τ)_i + ε/N`. Unvisited rooms get the highest visited LP, or 0 if none is visited. The first loss in a room sets both of its EMAs.
  - **Safety-net mode** (sticky once `m6Streak ≥ 2`; a checkup without M6 resets the streak). `stuckFor` counts the steps in a row in which every visited room has LP < `caregiverThreshold`. It decides only when `stuckFor ≥ caregiverStuckSteps`, then resets `stuckFor`.
  - **No move.** A pick equal to `current` returns null and is not a carry.
